## 阶段一：项目结构梳理

把整个仓库想成「一个厨房、两扇门、一本菜谱」。`sky-take-out` 是后厨：Maven 多模块 Spring Boot 2.7.3，父工程只做依赖版本管理。`sky-common` 放全项目共用的东西——统一返回体 `Result`/`PageResult`、JWT/OSS/微信支付工具、业务常量和异常、ThreadLocal 里的当前登录人 `BaseContext`。`sky-pojo` 是菜谱上的「菜名和配料表」：`entity` 对数据库，`dto` 是请求入参，`vo` 是返回给前端的视图。真正干活的是 `sky-server`：`controller.admin` 给商家后台，`controller.user` 给小程序，`controller.notify` 接微信支付回调（不走 JWT）；`service` 写业务，`mapper` + `resources/mapper/*.xml` 写 SQL；`interceptor` 校验 token，`aspect` 给插入/更新自动填创建人时间，`task` 每分钟取消超时未支付单、凌晨自动完成配送单，`websocket` 给后台推新订单和催单。配置从 `application.yml` 进，具体账号密码在 `application-dev.yml`，敏感项已改成 `SKY_*` 环境变量，本地仍有开发默认值。文档入口是 SpringDoc：`http://localhost:8080/swagger-ui/index.html`。

`project-rjwm-admin-vue-ts` 是商家这扇门，Vue 2 + TypeScript + Element UI + Vuex。`src/api` 按业务拆 axios 封装；`src/views` 是页面；`src/layout` 是壳子（侧栏、顶栏、改密弹窗）；`src/store/modules` 只有 `app`（侧栏、未读数）和 `user`（token、登录信息），不要再塞 Redux 或 Zustand，技术栈已经定了。`vue.config.js` 把开发服开在 8081，把 `/api` 剥掉前缀转到 `http://localhost:8080/admin`。`permission.ts` 只看 cookie 里有没有 `token`，没有角色权限。`nginx-1.20.2` 是第三种打开方式：8888 端口托管已经打好的静态包 `html/sky`，同样把 `/api/` 转到后端 `/admin/`，并把 `/ws/` 升级成 WebSocket。`database/sky.sql` 是 11 张业务表的建库脚本；`security_hardening.sql` 把员工密码列加宽到能存 BCrypt，并补索引。店铺营业状态不在 MySQL 里，只在 Redis 的 `SHOP_STATUS`。`docs` 里有 OpenAPI 快照和上次接口测试报告。C 端小程序不在本仓库，README 指向外部 `project-rjwm-weixin-uniapp`。

请求怎么走：浏览器 `GET /api/shop/status` → 开发代理或 nginx 变成 `GET /admin/shop/status` → `JwtTokenAdminInterceptor` 读请求头 `token` → `ShopController` → `ShopService` 读写 Redis。用户端走 `/user/**`，请求头是 `authentication`。支付成功走 `/notify/paySuccess`，没有拦截器。这就是全貌：一套后端，管理端 SPA 一份源码加一份 nginx 产物，用户端源码不在这里。

## 阶段二：环境启动与前端检查

本机 Node 默认是 22，直接 `npm run serve` 会因 OpenSSL 和 `node-fibers` 的 ABI 直接崩掉。切到已安装的 Node 14.21.3（`E:\nvm\v14.21.3`）后开发服才起来。建议把这个项目的 Node 钉在 14，或在文档里写清 `nvm use 14.21.3`。nginx 预编译包可以当对照：不需要编译就能看页面壳子，接口走同一套代理。

用真实 token 打过管理端各页依赖的接口。登录、员工分页、分类、菜品、工作台四件套、店铺状态、营业额/用户/订单/TOP10 报表均 `code=1`。员工不存在 id 已返回业务失败而不再 500。菜品 24 条在售，分类 10 条。套餐列表 `total=0`，订单列表 `total=0`，报表数字全是 0：库里几乎没有套餐和订单种子，页面会空，这不是接口挂了。导出运营报表 `GET /admin/report/export` 运行时 500，根因是 classpath 里没有 `template/运营数据报表模板.xlsx`，`XSSFWorkbook` 对空流 NPE。修改密码 `PUT /admin/employee/editPassword` 405，通知中心 `/messages/*` 404，图片下载 `/common/download` 404，旧报表 ` /report/dataOverView` 404——这四处是「页面或 API 封装还在、后端没有对应资源」。

按路由逐页看代码和接口对齐情况。`/login` 表单默认 admin/123456，明文提交，和后端 BCrypt/MD5/明文兼容校验匹配，实测登录成功。`/dashboard` 工作台四个 overview 接口都通，导入了但未调用的 `getDataOverView` 是死代码，不影响渲染。`/order` 搜索和状态统计通，但详情 `GET /admin/order/details/{id}`、完成 `PUT /admin/order/complete/{id}` 的方法参数没有 `@PathVariable`，Spring 会按 query 绑定；前端把 id 放在路径上。当前没有订单所以看不出，一旦有单，「查看详情 / 完成」会拿不到 id。派送接口写了 `@PathVariable`，是对的。`/category`、`/dish`、`/employee` 的分页和启停路径与后端一致。`/dish/add` 上传走 `POST /api/common/upload`，成功时把 `response.data` 当 OSS 地址用，这是对的；后端现在会因类型或大小返回 `code=0`，组件 `on-success` 没有判断 `code`，失败时可能当成成功。`/setmeal` 列表为空是数据问题。`/statistics` 四张图接口通，导出按钮会 500。`/inform` 一进页就打 `/messages/page`，必 404。顶栏通知角标方法写了但 Navbar 里没有调用，所以平时不会刷 404；进通知中心才会爆。顶栏营业状态读写已对齐 Redis 方案。改密弹窗会 405。刷新页面后 `token` 还在所以进得去，但登录时写入的 cookie 键是 `user_info`，读取函数认的是 `userInfo`，Vuex 的 `userInfo` 也不会从 cookie 水合，右上角姓名会空。WebSocket 地址 `ws://localhost:8080/ws/{随机id}` 与后端一致，无单时只能确认连接逻辑在。`/404` 静态资源存在。未挂路由的 `views/chart/index.vue` 加上整份 `charts.ts` 是旧报表，点不到，属于死页面。

性能上开发服开了 `source-map` 且 `css.extract` 在 development 也被当成生产提取，热更新会偏慢，可接受。生产包 `shopTable` 这一chunk 约 120KB，是订单/菜品/套餐挤在同一异步名上的结果，可按路由拆。axios 超时 600 秒过长。请求去重 `requestOptimize` 对分页连点有用，对导出 blob 要小心别误伤。初步修复顺序：补 Excel 模板并空流防护；给 `details`/`complete` 加 `@PathVariable`；实现或下线改密；通知中心要么接 WebSocket 落库要么暂时摘菜单；统一 cookie 键并在 store 初始化时恢复 `userInfo`；上传成功回调判断 `code===1`；开发用 Node 14。这些改动都不需要新状态库。

## 阶段三：管理端新增功能与前端联动方案

对照课程版苍穹外卖，后端最近补的是安全与工程化，不是新的 C 端业务。BCrypt 登录升级、密码列加宽、员工接口脱敏、店铺状态抽成 `ShopService`、上传白名单和大小限制、地址/订单归属校验、SpringDoc 替换 Knife4j、密钥改环境变量。这些里真正「管理端该有、页面却接不上」的，不是小程序那套 `/user/**`，而是三条商家侧能力：改密链路只做了一半、通知中心只有前端、报表导出缺模板。下面按数据流讲，方便你自己动手。

改密是最值得先做的闭环。库表还是 `employee.password`，现在可能是 `$2a$` 开头的 BCrypt，也可能是遗留 MD5。后端已经有 `PasswordEditDTO(empId, oldPassword, newPassword)`、`PasswordEditFailedException` 和文案常量，`EmployeeService` 却没有方法，`EmployeeController` 也没有 `PUT /admin/employee/editPassword`。前端顶栏「修改密码」已经组好 `{ oldPassword, newPassword }` 明文 PUT 出去。补法是在 Service 里用当前 `BaseContext` 的员工 id（不要信前端传来的 empId，防止改别人的密码），`passwordEncoder.matches` 校验旧密码，校验失败抛业务异常，成功则 `encode` 新密码写回。Controller 加 PUT，拦截器不用改，已经覆盖 `/admin/**`。前端弹窗成功后提示并建议重新登录。Vuex 不必加字段，这是一次性写操作。原理就是「证明你还知道旧密码，再把新密码按现在的哈希规则存」；empId 从 token 出，是因为 token 里的人就是操作者。

通知中心是另一类缺口。页面 `views/inform/index.vue` 按 `type` 渲染待接单、催单等，接口假定有 `messages` 表和 `/messages/page|countUnread|batch|{id}`。本库 11 张表里没有 messages，WebSocket 倒是已经在支付成功和催单时广播 `{type, orderId, content}`。有两条路。轻量做法：不建表，Navbar 收到 socket 后把消息推进 Vuex `app.notices`（数组 + unreadCount），通知页只读这份内存；刷新会丢，但对商家值班台够用，也避免假接口 404。完整做法：建 `message(id, type, order_id, content, is_read, create_time)`，支付成功和催单时除了 socket 再 insert 一行，管理端提供分页和已读接口，进页拉历史、socket 只负责实时。角标用现成的 `AppModule.statusNumber`，Navbar 的 `getCountUnread` 要在 `mounted` 里真正调用，现在写了却没跑。不要引入 Zustand，未读数已经在 Vuex 里。

报表导出后端方法在，前端「数据统计」标题栏也会调 `exportInfor()` 要 blob，缺的是 `sky-server/src/main/resources/template/运营数据报表模板.xlsx`（课程资料那份，Sheet1 第 2 行日期、第 4–5 行概览、从第 8 行起 30 天明细）。补上模板后重新打包。代码里要对 `inputStream == null` 直接返回业务错误，避免再 500。前端已设 `responseType: 'blob'`，记得用 `URL.createObjectURL` 触发下载，并识别 JSON 错误体（axios 在 500 时 blob 里其实是 HTML/JSON）。工作台和四张统计图已经对上 `/admin/workspace/*` 与 `/admin/report/*`，不用新页面。

还有几处管理端才能碰到、建议顺手改的契约。订单详情和完成必须 `@PathVariable Long id`，否则路径里的 id 进不了方法。上传组件在 `handleAvatarSuccess` 里判断 `response.code === 1` 再赋图片地址，否则把后端的「类型/大小错误」提示出来。cookie 键统一成 `userInfo`，`User` 模块初始化时 `JSON.parse(getUserInfo()||'{}')`，刷新后顶栏才有名字。`charts.ts` 和 `views/chart` 没有路由，删或注释即可，避免以后误接到不存在的 `/report/amountCollect`。SpringDoc 给开发看就够了，不必做进菜单。BCrypt 对前端是透明的，登录和改密都继续传明文，哈希只发生在服务端。

动手顺序建议：PathVariable 和导出模板（现有页立刻可用）→ 改密接口（弹窗从 405 变成功）→ 通知中心选轻量 Vuex 或落库 → cookie 水合和上传 `code` 判断。每一处都是「已有页面补契约」，不是新开一套状态管理。

## 阶段四：Cloud Agent 自动演示（已完成）

云端按默认值起了 MySQL 8（`root/123456`，导入 `sky.sql`）、Redis、JDK17 后端 8080、Node 14 管理端 8081，OSS 密钥留空。账号 `admin / 123456`。走的是 GitHub `origin/main`，**不含你本机未提交的上传白名单和 ShopService 空值防护**，所以个别失败形态和本机最新代码会不一样。跟屏：[管理端演示](bc-96af62a4-f2e2-41b8-9cd4-5361b5faa648)、[Try Live](bc-96af62a4-f2e2-41b8-9cd4-5361b5faa648#desktop)。视频：`admin_ui_walkthrough_login_pages_upload_failures.mp4`。

登录进工作台（今日数据 0、菜品启售 24、套餐/订单空）→ 订单空表但 Tab 和筛选在 → 分类搜「烤鱼」得到蜀味烤鱼 → 菜品列表能进添加页 → 套餐空 → 统计图全 0、导出 `GET /api/report/export` 500（缺 Excel 模板，页面几乎无 toast）→ 员工列表有 admin → 通知中心 `GET /api/messages/page` 404 但仍画空态 → 营业状态营业中/打烊中可来回切（Redis）→ 改密 `PUT /employee/editPassword` 405 → 退出回到登录页。全程未保存菜品、未删员工。

无 OSS 传合法小 PNG：用户看到红色 toast「图片上传失败」，框仍空，没有裂图假 URL。Network 是 `POST /api/common/upload` **HTTP 500**。原因是 `OSSClientBuilder.build()` 在 `AliOssUtil` 的 try 外面，空 AccessKey 在建客户端就抛，进不了吞掉 `OSSException` 仍拼假 URL 的分支；Controller 只 catch `IOException`，所以 500，前端走 `on-error`。若 AK 填了但无效，才更容易出现 200 + 假地址。超 2MB 的 jpg：toast「上传文件大小不能超过2M!」，**0 次** upload 请求，这是前端 `beforeAvatarUpload`。强制选 `bad.txt`：云端 `main` 没有类型白名单，一样打到 OSS 再 500，toast 仍是「图片上传失败」，**不是** `code=0 不支持的文件类型`。你本机未提交的 `CommonController` 会在进 OSS 前按后缀拦截 `.txt`，本地复现会更干净。

## 最终交付汇总

项目是标准苍穹外卖三模块后端加 Vue2 管理端，nginx 托管生产包，小程序不在本仓。核心配置是 8080 + Redis 店铺状态 + JWT 头 `token` + `/api` 到 `/admin` 的代理。本机后端和两端静态入口已打通，主业务读接口可用；套餐和订单无数据导致空页；导出 500、改密 405、通知 404 已用运行时响应证实；订单详情/完成的路径参数绑定是隐患。前端联动优先补改密后端、导出模板、通知（Vuex 或表）、`@PathVariable`、cookie 与上传校验，继续用现有 Vuex，不要上 Redux/Zustand。Cloud Agent 已按无 OSS 录完管理端全流程；上传失败表现为 500+「图片上传失败」，超大文件被前端 2M 拦住；`.txt` 在远程 `main` 上未走类型白名单。
